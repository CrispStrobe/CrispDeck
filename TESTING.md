# CrispDeck — testing checklist

> Generated by `scripts/testing-checklist.mjs` from the source, and
> pinned by `src/lib/testing-checklist.test.ts`. Do not edit by hand:
> add a column type or a route and regenerate, or the guard fails.

This is PLAN item 174 — connect real accounts and use the app for a day.
It is the highest-value work left and the part no test can do. Errors
swallowed along the way land in the in-app log viewer, which has a
download button; export it at the end and the session leaves evidence
rather than impressions.

For each item: does it work, is it confusing, would you use it?
